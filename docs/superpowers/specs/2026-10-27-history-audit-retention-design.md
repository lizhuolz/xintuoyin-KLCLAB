# 对话删除与平台审计留存

用户已确认：用户删除仅隐藏个人记录，平台保留原文；接口路径、请求参数和响应格式不变，修改内部逻辑并用 Git 管理。

## 设计

继续使用 `history/<date>/<conversation_id>.json` 保存原文。用户单条、批量删除只在同一 MinIO 桶的独立 `history_visibility/` 前缀写隐藏标记，绝不删除或重写原文、附件及其时间戳。按服务端已验证的租户 ID 和用户 ID 计算隔离键，不依赖姓名、前端用户字段或 accessToken 的具体值。游客沿用现有按请求 IP 区分身份的限制，同 IP 游客不能独立区分。

个人列表在分页前过滤隐藏记录，个人详情及导出同样排除；平台列表、详情和导出读取原文，不使用个人隐藏标记。标记不存在的旧记录默认可见，无需数据迁移。单独存标记可避免正在执行的聊天保存覆盖删除状态。重复删除成功；写标记失败按原有单条错误 / 批量成功 ID 列表报告；读取标记失败返回错误，不能将失败误认为没有隐藏记录。

平台已有显式删除接口继续执行原有物理删除语义，与用户删除函数解绑；修正其批量删除调用未定义函数的问题。本次不新增路由、依赖、登录方式或权限规则，不进行历史记录的批量迁移或真实删除。既有个人列表的姓名筛选、平台鉴权设计不在本次改动范围；个人隐藏不是访问权限机制。

## 取舍

- 直接在原文添加删除字段较短，但会改动审计对象，并与聊天保存相互覆盖，不采用。
- 独立复制平台档案需要迁移、双写及一致性处理，不采用。
- 选择独立隐藏标记，维持原有审计存储路径，减少改动。

## 验收

内存存储 + 真实接口处理函数测试：单删和批删后个人不可见、平台仍能列表/详情/导出，原文和附件字节不变；跨用户/租户隔离；标记写入及读取失败；重复删除；分页搜索；并发聊天旧快照保存；平台显式删除保持行为。比较全部路由装饰器与函数参数确保接口契约不变。运行既有上传、数据库权限、图谱回归；不对线上真实对话调用删除。

已被物理删除的旧记录无法通过本次改动恢复；回滚代码后旧版本不会识别隐藏标记，个人列表会重新显示仍留存的原文。
