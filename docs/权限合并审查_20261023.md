# xty Text2SQL 权限合并审查与使用说明

本次将 `/data4/cyn/code/xty_proj_ctrl` 的数据库问答权限功能选择性合并至 `/data2/dlx/projects/xty`。不采用整个 backend 覆盖。

## 权限规则

身份沿用现有 Redis `accessToken` 解析，授权参数只由服务端上下文提供。普通员工必须有有效 `tenant_id` 和 `staff_id`；企业管理员必须有有效 `tenant_id`。不能以账号 ID 代替员工 ID，客户端 `user_identity` 不作为 SQL 授权来源。

- 所有业务表必须属于资源白名单并具有 `TENANT_ID`；每次物理表访问都强制限制当前租户。
- 含 `OPERATER_STATUS` 的表只读取有效记录。
- 普通员工仅能访问 `t_project_user` 有效关联的项目；项目主表按 ID、明细表按 PROJECT_ID 过滤。管理员可查询本租户所有有效项目。
- 项目关联无法核验、未知表、跨库、写操作、危险函数、多语句及模糊表来源均拒绝执行。
- SQL 权限拒绝不自动回退知识库。每次 SQL 调用独立创建/关闭 DB，不共用用户状态。

## 当前边界

这是 Text2SQL 的租户和项目数据隔离，不是整个 xty 的完整权限体系。普通员工与管理员使用同一业务表白名单，主要区别是项目行范围；非项目表（包括工资类表）目前主要按租户过滤，没有新增工资/字段/部门等更细规则。若需要普通员工只查本人工资或按岗位分表，必须另行定义业务授权策略。

知识库与图谱权限未在本次完善；原有 `/api/admin/kb/*`、`/api/admin/db/*` 缺少角色校验的问题仍存在，不能将此次合并作为它们已完成权限验收的依据。

工具当前由应用层校验保证只读，并非 MySQL 原生行权限。每次查询需要读取元数据，存在初始化成本；1000 行结果上限不是服务器执行耗时上限。
