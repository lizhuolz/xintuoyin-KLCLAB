# 数据库 Agent 优化合并

## 目标与来源

合并 `/data4/cyn/code/xty_proj_ctrl/backend` 中经过审查的 SQL 能力优化，保留当前 xty 的接口、租户与项目隔离、日期表达式兼容、历史审计留存、上传与图谱修复。来源为同学未提交的工作目录，因此用文件内容 SHA-256 记录审查版本。

## 合并选择

采用增量合并，保留当前 `sql_permissions.py` 的完整物理表/CTE 来源分类和七种日期表达式类型；同学版本的完整覆盖会回退这些检查。现有知识库、存储、鉴权和环境配置不随参考目录覆盖。

引入实际字段及存储格式提示、生成 SQL 的语义校验、独立 SQL 调度器、结构化证据与受约束的答案渲染。数据为空时按 SQL 空集回答，不用知识库示例替代实时业务结果。流式响应在工具结果返回后用现有 `answer_replace` 事件清除先前中间答案，避免与最终 SQL 结果拼接。

## 必要适配

- 原问题与历史/附件上下文分开传递。数据库工具对外仍只有 `question` 参数，权限身份和背景来自服务端配置快照。系统控制指令不作为用户问题，问题提取识别真实生产提示标记。
- 机器 JSON 输出关闭模型思考并禁止未验收候选答案流出。
- 结构化查询契约失败时回退普通受权限校验的 SQL 生成；失败的已编译契约清除缓存，避免重复执行同一错误。
- 主键字面量绑定保留符号，防止问题中的负数被错认成正数。
- 同一查询包含不同对象的独立事实时回退普通 SQL，避免第一个对象不存在导致其余对象的有效结果也被丢弃；同一对象的多属性及关系判断仍可编译。
- 无法证实来源的数值不自动视为可计算指标；员工和项目 ID 不参与普通金额/数量求和。
- 表白名单、单条只读、租户、有效记录及普通用户项目过滤继续执行。仅补充经核查的纯 MySQL 函数及无副作用 DUAL 语法规范化。

## 验证与版本管理

当前基线 40 项 SQL 回归已通过。新增同学的离线测试，并对上述集成缺陷先复现再修复。最终 191 项后端测试、95 项现有上传/图谱/鉴权/知识库/问答/历史回归通过；60 个路由及 1 个启动事件的装饰器和参数签名保持一致。

使用现有本地 Qwen3.5-27B 和实际配置 MySQL 做了 3 组只读验收：企业项目计数、明确指定日期及状态条件的项目计数、指定项目 ID 的属性查询，结果均与直接读取的基准一致，执行 SQL 保留租户及有效记录过滤。该验收使用显式测试身份，不代表 Redis 登录已验证。另以合成结果验证了实际模型和 LangGraph 的受约束回答流，只向用户输出经校验的表格。

测试时后端 8000 和 MinIO 9000 均未运行，Redis 连接超时，MySQL 与本地模型可用。因此尚未验证真实登录到 HTTP 问答的完整流程；本次仅合并源代码，不启动或重启这些服务。模型回答校验失败时会显示已有数据表及校验提示，而不会直接输出未经证实的数值推断。
